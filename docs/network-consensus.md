# libp2p 与开发用 PoW

本轮实现固定低难度的工作量证明链，不兼容比特币的交易、脚本、P2P 协议或经济规则。工作量证明和通信是独立插件；网络身份只用于连接认证，不代表共识投票权。

## 能力与边界

core.WorkProtocol 在最小对象接口之外提供 Parent、Work 与可取消 Seal；具体 PoW 协议决定格式和验算规则。protocol/powkv 复用 KV 交易的签名和执行语义，但区块具有独立 PoW 格式与协议身份，不把 nonce 等字段加到所有区块。

core.BranchLedger.Import 保存验证后的任意已知父块分支，以本地验算的工作量累积决定主链；不接收远端声称的累计工作量。严格更重才切换，同权暂留当前链。分支保存独立状态快照，主链切换时确认交易与回执索引随链头原子替换。共识接入负责按新主链重新检查被撤销分支的交易。

示例协议固定要求区块 ID 的首字节为零（8 位目标），每个有效非创世块计 256 单位工作量；创世为零。该规则由协议版本固定，区块不能自报一个更容易的目标。挖矿从随机 nonce 起点搜索，多个矿工不必重复同一搜索序列。

固定难度、无奖励、无自动调难；空区块可正常挖掘。低难度用于测试节点竞争和重组，不适合承载有价值资产。网络分区期间双方均可继续出块，恢复连接后按累计工作量收敛；同权分区需要后续区块打破平局。

## libp2p 传输配置

network/libp2p 支持 identityPath、listen、seeds、maxMessageBytes 和 timeout。正式开发配置应指定 identityPath，身份文件权限为 0600；不指定时每次生成临时身份。listen 与 seeds 使用 libp2p multiaddr，种子地址须包含对方 peer ID。

请求协议在进入业务处理前比较协议描述符及规范创世区块的 SHA-256 指纹。不同链即使协议名称相同也不能互通。节点地址和错误消息不会代替链协议验算。

默认 payload 上限 4 MiB、超时 5 秒，入站与出站各最多 32 个并行请求。帧在分配读取缓冲前检查长度；业务接入仍需限制块批次、祖先查询及交易数量。Connect、流读写和等待出站预算均受超时或调用者取消约束。种子连接失败会定期重试，节点关闭时取消重连并等待请求处理结束。

Network 是由根 Node resources 管理的生命周期资源；共识使用同一实例，请勿另行手动启动关闭。无效网络输入应拒绝并继续服务；存储故障须向根运行器上报。

## 启动多节点

```sh
go run ./cmd/gochainkit --config presets/pow.yaml
```

默认监听本机 19001，数据文件为 data/pow-chain.db，身份为 data/pow-peer.key。命令行启动后打印 Listening 地址，包含连接所需 peer ID。

复制 preset 为第二、第三个配置；分别使用独立数据库、身份路径及监听端口，例如 19002 和 19003。把第一个节点打印的完整地址写入其他节点 network.config.seeds，种子连接会自动重试。节点必须使用相同协议配置和创世，复用旧 KV 数据库会被拒绝。

consensus/pow 配置 interval 控制挖矿尝试间隔，syncInterval 控制同步轮询；mining 默认为 true，设 false 即只同步。停机可使用中断信号或 CLI 的 --run-for。关闭多个矿工后用 mining: false 重启同一批数据，连接到更重链可继续追赶；同权分支需要后续工作量打破平局。

同步采用分页的主链区块和本地验证，不将其他节点的链头声明直接当作可信状态。接收块在父块快照上重执行、验证工作量后再导入；同步游标与二进制 ID 在传输中保持字节形式。资源与消息限制属于开发默认值，大规模部署仍需压力测试与可观测性完善。
