# libp2p 与开发用 PoW

本轮实现固定低难度的工作量证明链，不兼容比特币的交易、脚本、P2P 协议或经济规则。工作量证明和通信是独立插件；网络身份只用于连接认证，不代表共识投票权。

## 能力与边界

cap/consensus.WorkProtocol 在最小对象接口之外提供 Parent、Work 与可取消 Seal；具体 PoW 协议决定格式和验算规则。protocol/powkv 复用 KV 交易的签名和执行语义，但区块具有独立 PoW 格式与协议身份，不把 nonce 等字段加到所有区块。

cap/chain.BranchLedger.Import 保存验证后的任意已知父块分支，选链与最终性由注入的 BranchPolicy 决定，存储只保存不透明分数。PoW 策略以本地验算的累计工作量选链，不接收远端声称的累计工作量；严格更重才切换，同权暂留当前链。分支保存独立状态快照，主链切换时确认交易与回执索引随链头原子替换。importer/branch 负责完整验证、执行、导入，以及按新主链重新检查被撤销分支的交易。

示例协议固定要求区块 ID 的首字节为零（8 位目标），每个有效非创世块计 256 单位工作量；创世为零。该规则由协议版本固定，区块不能自报一个更容易的目标。挖矿从随机 nonce 起点搜索，多个矿工不必重复同一搜索序列。

固定难度、无奖励、无自动调难；空区块可正常挖掘。低难度用于测试节点竞争和重组，不适合承载有价值资产。网络分区期间双方均可继续出块，恢复连接后按累计工作量收敛；同权分区需要后续区块打破平局。

## libp2p 传输配置

network/libp2p 支持 listen、seeds、maxMessageBytes 和 timeout，通过 Deps 注入 Libp2pIdentity；网络本身不读写密钥文件。身份适配器使用 Store 持久化密钥，默认开发图采用加密文件与环境口令来源。未配置身份依赖会在构造时失败，不再隐式生成临时身份。listen 与 seeds 使用 libp2p multiaddr，种子地址须包含对方 peer ID。详见 [密钥保存](key-management.md)。

请求协议在进入业务处理前比较协议描述符及规范创世区块的 SHA-256 指纹。不同链即使协议名称相同也不能互通。节点地址和错误消息不会代替链协议验算。

默认 payload 上限 4 MiB、超时 5 秒，入站与出站各最多 32 个并行请求。帧在分配读取缓冲前检查长度；业务接入仍需限制块批次、祖先查询及交易数量。Connect、流读写和等待出站预算均受超时或调用者取消约束。种子连接失败会定期重试，节点关闭时取消重连并等待请求处理结束。

Network 是由根 Node resources 管理的生命周期资源；共识使用同一实例，请勿另行手动启动关闭。无效网络输入应拒绝并继续服务；存储故障须向根运行器上报。

## 启动多节点

```sh
go run ./cmd/gochainkit --config presets/pow.yaml
```

默认监听本机 19001，数据文件为 data/pow-chain.db。身份由 keystore 保存，启动前须通过 GOCHAINKIT_KEYSTORE_PASSWORD 环境变量提供该保存目录的口令；口令不写进 YAML。命令行启动后打印 Listening 地址，包含连接所需 peer ID。

复制 preset 为第二、第三个配置；分别使用独立数据库、密钥目录及监听端口，例如 19002 和 19003。把第一个节点打印的完整地址写入其他节点 network.config.seeds，种子连接会自动重试。节点必须使用相同协议配置和创世，复用旧 KV 数据库会被拒绝。旧明文 identityPath 不会被自动导入或覆盖；切换身份保存前先按密钥文档显式导入，或按新 PeerID 更新连接地址。

consensus/pow 的 interval 控制挖矿尝试间隔，mining 默认为 true，设 false 即只监督同步服务。同步轮询由独立 sync/chain 插件的 interval 配置控制；旧 consensus.config.syncInterval 已移除。停机可使用中断信号或 CLI 的 --run-for。关闭多个矿工后用 mining: false 重启同一批数据，连接到更重链可继续追赶；同权分支需要后续工作量打破平局。

同步采用分页的主链区块和本地验证，不将其他节点的链头声明直接当作可信状态。接收块在父块快照上重执行、验证工作量后再导入；同步游标与二进制 ID 在传输中保持字节形式。资源与消息限制属于开发默认值，大规模部署仍需压力测试与可观测性完善。


## 同步、导入与共识装配

`importer/branch` 通过 `ImportDeps` 接收分支协议、账本、执行器和交易池，负责一次完整的验块、执行、原子导入及重组后的交易池维护。保存未切为主链的有效分支时，也会回收其中尚未在当前主链确认的交易，避免独立矿工只能通过追上源链才看到已从源节点交易池移除的交易；不因此改变选链或同分保持当前链头的规则。已提交后的维护失败保留 `CommittedError`，清理使用独立限时上下文，正常停机不会取消已成功提交后的必要清理。

`sync/chain` 通过 `SyncDeps` 接收分支协议、只读账本视图、交易池、网络和导入器，负责主链分页追赶及交易传播。它独占同一 Network 的 Handler；停止时拒绝新请求、取消并等待已进入的处理器，再上报故障。一个 Network 不能同时由其他插件覆盖 Handler。后续需要共用其他消息类型时，应显式注入统一路由器。

`consensus/pow` 只负责构块、封印调度与监督，通过 `PoWDeps` 接收协议、账本视图、构块器、导入器和同步服务；不隐藏创建子插件。链头改变时取消旧父块上的挖矿。同步和导入不要求 `WorkProtocol`，其他使用单父块分支的共识可以复用；多父块或 DAG 同步需要独立实现对应能力。

构造时同时检查协议描述符和同一个 `LedgerID`，防止同协议的不同账本被误装配。网络对端的无效输入只拒绝该请求；本地依赖故障通过 `LocalServiceError` 上报，不因为与取消或交易错误同时发生而被吞掉。

成功保存但未切换到主链的合法分支，其交易若尚未被当前主链确认，也会尝试回收到交易池；否则源节点确认后停止传播交易，而独立矿工又可能长期保持各自同工作量分支，交易会滞留侧链。该回收与重组回收共享逻辑，不改变选链或交易执行规则；交易池容量及本地状态相关构块校验仍生效。保存后维护失败仍返回 CommittedError。
