# 单节点内存出块

本阶段实现 PluginKit 可装配的构块与提交闭环，作为后续持久化的行为基线。

后续接口已协议化，当前定义以 [模块与协议接口](interfaces.md) 为准。默认 KV 区块与交易只是一个协议实现，通用模块还通过另一种自定义格式的出块与恢复测试。

## 模块

- `mempool/memory`：保存有界待处理交易。
- `protocol/kv`：默认格式、编解码、构块与验证规则；通过依赖图注入。
- `executor/kv`：验证签名与连续序号，在发送者命名空间内写入键值，序号纳入状态根。
- `storage/memory`：提供创世块、快照、区块与回执查询及锁内原子提交。
- `builder/basic`：选取交易、隔离执行、计算根并绑定候选结果；不移除交易。
- `node/coordinator`：重新执行验证提议，提交成功后清理交易池。
- `consensus/single`：按固定间隔驱动提议、验证、提交；错误终止运行，取消时退出。

Coordinator 位于 node 层，不导入插件实现。plugins/node/coordinator 仅提供 PluginKit 构造适配。

## 数据和接口补充

默认 KV 区块 ID 使用域分离的规范头部编码。它的交易根和回执根是列表哈希，不提供 Merkle 包含证明；其他协议可以使用自己的格式和承诺算法。

StateReader 增加 Entries 方法，返回调用者拥有的完整快照，以供第一版执行器计算状态根。它不是大规模状态后端的最终性能接口；后续可在契约评审后改为有界迭代或可更新状态树。

## 验证入口

```sh
go test ./tests/integration -v
```

集成测试验证签名交易入池、构块、执行、提交、状态与回执查询、清理池，以及后续定时空块；另验证真实 PluginKit 依赖图复用同一存储实例。

失败路径包含父状态隔离、错误写入集被拒绝且链头不变、重复提交识别、重复序号拒绝、协调器提交失败不清理交易、无效提议拒绝及取消退出。

## 下一阶段

用事务数据库替换内存后端，保持接口行为：区块、状态、回执与链头一起提交。先验证正常重启，再做故障注入及子进程中断恢复，不能仅靠正常关闭证明崩溃一致性。

本阶段没有持久化、独立节点命令、对等网络或分布式共识保证。内存历史状态随进程退出丢失。
