# 兼容、备份恢复与排错

本页组织已有行为，不提供尚不存在的迁移工具或生产运维承诺。具体磁盘语义以 [存储规范](../storage.md)、密钥语义以 [密钥指南](../key-management.md) 为准。

## 区分变更

- 本地参数：数据库/密钥路径、端口、seeds、生产者本地身份等；修改也可能需要停机，且不得误指向另一账本。
- 链参数：规范编码、ID/签名域、模型与规则配置、创世、选链身份、执行/计量语义；不能当作普通热配置修改。ProtocolDescriptor 相同不证明语义相同。
- Go API、HTTP、线上协议、本地磁盘格式是不同版本面。当前 core/cap 的长期冻结承诺待确认；草案接口可变，不能从编译通过推断跨版本兼容。

当前 Bolt 格式 2 拒绝旧格式 1、错误协议/创世及缺失必要策略身份的数据；普通线性 KV 的兼容例外见存储规范。没有自动迁移、自动覆盖或“忽略绑定继续打开”流程。

## 开发环境备份与恢复

1. 记录代码/二进制版本、完整配置、协议/创世身份及实际数据库和密钥路径；相对路径基于进程 cwd。
2. 正常停止节点，等待所有 worker 退出和数据库关闭。若异常退出，保留原件，不先用新协议写入。
3. 复制已关闭数据库、配置与密钥目录到独立备份；口令来源单独安全保存。复制运行中的文件不在本指南保证范围内。
4. 在新的独立目录验证副本，使用相同版本/配置/口令，调整本地监听端口以免冲突。核对旧区块、确认交易、状态与 PeerID，再允许继续写入。
5. 版本或绑定被拒绝时，回到备份与兼容性设计，不能删除旧库或重新初始化密钥“修复”。需要真实迁移时另立可回滚方案。

P2P 身份和共识密钥不是同一种记录；观察节点无需复制验证者私钥。旧明文 identityPath 需显式应用级导入，Store.Create 不覆盖现有记录；详见密钥指南。错误口令不意味着应该重建身份。

## 排错入口

| 症状 | 首先核对 | 不应推断 |
| --- | --- | --- |
| HTTP/P2P 监听失败 | 日志、端口、配置副本与进程 cwd | 不停止未知进程或重置数据 |
| 库被占用/恢复失败 | 是否另一实例占用、版本/协议/创世/策略、权限与原始错误 | 不删除锁/数据库或静默降级 |
| accepted 但未 confirmed | 保存 ID 查询、nonce/余额/输入、池预算、生产者/同步状态 | 受理不保证上链，超时不等于未受理 |
| 节点不互通 | 协议/创世一致、seeds 完整 PeerID、独立监听/身份目录 | 名称相同不等于同一链 |
| 同权分叉未收敛 | PoW 后继工作量或 PoA 的具体 Choice、连接状态 | 不同策略的平局规则不一样 |
| PoA 不出块 | slot/时间、成员顺序、producer 编码、keyID/口令、是否观察者 | 单签不能宣称投票最终性 |
| 停机返回错误 | 混合故障和 CommittedError、worker 是否全部退出 | cancel 不意味着副作用撤销 |

## 安全和验证边界

API 默认本机监听，现有公开查询不是管理/钱包服务；公网部署需要单独威胁模型及访问控制设计。libp2p 身份认证不等于共识投票权。当前存储是开发规模完整快照与分支图，长期裁剪/性能未保证。正常重开、软件崩溃测试和硬件掉电验证是不同层次。
