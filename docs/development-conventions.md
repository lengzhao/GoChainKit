# GoChainKit 编程与模块接口规范

状态：2026 年 10 月 17 日已通过用户评审，作为首批实现约束。本文中的示例是约定草图，尚非已发布 API。

## 适用范围与依据

适用于框架维护者、插件作者和配置组装者。参考 AgentKit 的架构文档、schedule 和 compaction 插件、cap/compaction 接口及插件状态说明，并结合 PluginKit v0.1.6 的本地源码核对装配边界。

以下“必须”是建议在 GoChainKit 中采用的规则，不表示 AgentKit 所有实现均已满足这些规则。AgentKit 的代码用法是参考，不能替代 PluginKit 上游 API 契约。

## 1 分层与依赖

沿用 AgentKit 的原则：PluginKit 负责通用装配，领域框架定义语义，插件提供实现。

- `core/types`：协议数据、规范编码和公共值类型，不依赖插件、Node 或 PluginKit。
- `core/contracts`：领域接口与错误契约，可依赖公共类型，不依赖插件实现。
- `runtime/<capability>`：确有多个消费者需要的共享实现，不负责插件注册。
- `plugins/<capability>/<implementation>`：配置适配、构造、注册及具体实现。
- `node`：链运行协调与生命周期。普通协调代码依赖接口；若注册为根插件，将注册适配放在 `plugins/node/default`。
- `assembly`：导入选定插件并调用 PluginKit 构建依赖图。
- `cmd/gochainkit`：命令行、信号处理及程序退出。

生产插件包之间不得相互 import，包括为调用另一插件的 New 而建立的依赖。用 Deps 注入接口；共享算法提取到 runtime。仅 assembly、聚合注册包和集成测试可直接导入多个插件包。

AgentKit 使用根包和 cap 放置契约；本项目第一版沿用已评审草图中的 core/types 与 core/contracts，不同时建立另一套 cap 接口。后续确有拆包需求时再单独决策。

## 2 Go 编程习惯

- 使用 gofmt，包名小写，避免 util、common 等职责不明的包。
- Go 导出标识符使用正常 Go 命名；公共标识符注释说明语义，协议相关注释须写清边界。
- 使用小接口，不为每个结构体机械创建接口；接口围绕替换需求和消费方能力定义。
- 不使用包级可变变量保存节点、数据库、配置和请求状态。插件注册及不可变协议常量例外。
- 不用 panic 处理配置、交易或网络输入错误；启动装配失败返回 error。
- 错误增加模块和操作上下文，使用 `%w` 保留错误链；调用方用 errors.Is/As 分类，不匹配错误字符串。
- 不重复记录同一错误；最了解请求或运行边界的一层负责输出日志。日志不包含私钥、种子或完整鉴权凭证。
- 资源受容量、大小或时间约束，默认配置不得创建无限队列或无限后台任务。

## 3 插件注册与命名

Plugin Kind 使用 `能力/实现`，例如 `mempool/memory`、`executor/kv`、`consensus/single`。配置中的实例 ID 与 Kind 分离；一个 Kind 可实例化多次，实例状态不得串用。

每个插件包优先包含 `register.go`、配置与构造文件、实现文件和同包测试。单个很小的插件可合并文件，避免空目录和机械拆分。

`init()` 只注册类型，不做文件读写、联网、数据库打开或启动 goroutine。聚合注册包通过显式空白导入选择编译进二进制的插件。

直接调用上游 `pluginkit.Register`，禁止重新实现通用注册表、服务定位器或依赖容器。运行期间不从全局注册器查询业务依赖。

## 4 Config 与 Deps

沿用 AgentKit 的 Config/Deps 分离，以及通过 json tag 对齐 PluginKit 配置字段的习惯。

```go
type Config struct {
    MaxBytes int `json:"maxBytes"`
}

type Deps struct {
    Executor contracts.Executor `json:"executor"`
}

// constructor shape
func New(cfg Config, deps Deps) (contracts.BlockBuilder, error)
```

上例仅表示形状；正式代码需要真实声明、实现和测试。

- Config 放用户可序列化配置；Deps 放已构造的类型化依赖，不把服务实例塞入 Config。
- 使用上游支持的 `New()`、`New(Config)` 或 `New(Config, Deps)` 返回 `(T, error)`。
- 默认值通过上游 Defaulter 契约处理，合法性通过 Validator 契约处理；实现前核对准确方法签名。
- 默认值与校验不得依赖本机不可控环境，不得悄悄修正会改变链协议的错误值。
- 构造函数显式检查必需依赖、容量和配置组合；可选依赖必须说明缺失时语义。
- deps 不通过 context、全局变量或运行时服务定位器获取。
- 构造只做轻量初始化，I/O 资源获取和后台工作推迟到受控启动阶段。

## 5 接口契约必须说明的内容

每个公共接口必须在注释和契约测试中回答：

1. 调用前置条件与输入上限是什么？
2. 输入、输出是否复制，调用方能否修改切片或 map？
3. 是否可并发调用，顺序与一致性保证是什么？
4. 是否有外部副作用，失败可能发生在副作用之后吗？
5. 取消或超时如何传播？是否可能返回提交结果不确定？
6. 是否幂等，重复调用如何处理？
7. 返回哪些稳定错误类别？
8. 谁创建、关闭和释放资源？

耗时或可阻塞方法把 context.Context 放在第一个参数，不保存调用者的请求 context 供无期限使用。正常业务数据显式传参；context 不承载交易状态和依赖容器。

不把任意 `map[string]any` 作为模块间协议。它可出现在 PluginKit 配置装配入口；领域调用使用明确的 Go 类型。

## 6 生命周期与并发

Node 是运行生命周期 owner，按拓扑顺序启动，逆序关闭；对共享实例去重，禁止重复关闭同一数据库。

启动部分失败要回滚已经启动的资源。Start/Stop 的可重入性、重复调用和失败状态在实现前明确；默认不支持 Stop 后重新 Start，重启创建新实例。

每个 goroutine 必须有 owner、终止信号和等待完成的路径。Stop 先拒绝新工作，再取消或排空运行任务，再释放资源；不以“发出 cancel”冒充“任务已退出”。关闭使用独立、有界 context，不能复用已经取消的请求 context。

不得持锁执行插件回调、网络访问或耗时执行。跨模块调用顺序与内部锁边界在涉及共享状态时写明。

## 7 区块链专属约束

这是在 AgentKit 通用插件习惯之上新增的领域规则。

- 共识执行不得依赖 map 遍历顺序、本地时钟、系统随机数、外部网络或节点私有配置。需要的值来自明确的协议输入。
- 签名输入、哈希输入、字段编码、排序、长度限制、错误处理和整数溢出策略都属于协议契约。
- 区块构建可以读取受控时间或提议者信息，但验证与执行必须按协议检查，不让本机环境改变同一输入的状态结果。
- 隔离执行不修改已提交状态；只有 Committer 可以推进已提交链头。
- 区块、状态、回执与链头原子提交；提交期间中断的结果通过查询确认。
- 交易池准入只是预检查，最终执行必须重新验证。缓存不能成为正确性的唯一依据。
- AgentKit 的临时 context 状态袋不能用作链状态、余额、序号、最终性记录或恢复依据。
- 本地配置与创世/协议配置分离。更换插件若改变编码、执行或共识语义，应按协议升级处理，不能作为普通热配置变更。

## 8 测试与审查

- 公共类型：编码 golden vectors、签名域隔离、边界和非法输入。
- 可替换接口：提供共享契约测试，验证不同实现满足相同语义。
- 插件：构造配置、缺失依赖、多实例隔离、资源关闭和错误传播。
- 装配：真实 PluginKit 构图验证，覆盖未知 Kind、类型不匹配、循环依赖。
- 执行与提交：确定性重放、隔离、重复调用、旧链头冲突、原子回滚和恢复。
- 并发：相关包运行 race 检测；不能以正常关闭重启替代崩溃恢复测试。

实现时先写能捕捉预期行为的测试并确认失败，再编写实现。交付前运行 gofmt、go test、go test -race 和 go vet，按实际结果报告，不以无测试的编译成功代表行为已验证。

## 9 新插件交付清单

- Kind、Config、Deps、返回接口和生命周期清楚。
- 不直接 import 其他生产插件，不读取全局配置。
- 最小配置可装配；错误配置能够在合适的边界被拒绝。
- 并发、取消、资源归属和错误语义有文档与测试。
- 协议相关行为有确定性与兼容性验证。
- 提供配置样例并更新插件目录；开发用实现显式标注限制。
