# 区块 状态与交易持久化

`storage/kv` 通过事务后端保存区块、完整状态快照、已确认交易索引、回执和链头；提交成功后才清理内存交易池。`backend/bolt` 使用 bbolt，`backend/memory` 提供同一后端契约的内存实现。选链、协议验证、记录编码和恢复规则属于账本，不属于数据库后端。

## 装配与生命周期

账本 Deps 注入 Protocol 和 Backend，可选 BranchPolicy；路径属于 backend/bolt 的 Config。构造函数不打开文件，账本 Start 调用后端 Open，恢复校验通过后发布数据库；Stop 关闭它拥有的句柄。每次 Open 返回独立拥有的句柄，不能把打开器当作共享的数据库实例，也不需要把后端另列为根节点资源。Bolt 文件权限为 0600，新建父目录权限为 0700，同一路径被占用时有限等待后返回错误。

`cap/storage` 只定义命名空间 KV 事务能力，不依赖区块、交易、签名、链头或共识。只读事务不暴露写操作，写回调失败或提交前取消会回滚；事务及命名空间句柄仅在回调期间有效。返回字节由调用方拥有，扫描按字节序确定排列。不得在事务回调内递归开启同一数据库事务或把句柄交给后台任务。

既有直接内存账本 `storage/memory` 保留为独立的开发参考实现；`storage/kv + backend/memory` 用于验证通用账本能替换后端。两者职责不同，不用兼容别名把它们混为同一实现。

链读取、状态快照与提交三个依赖必须引用同一个 storage 实例。测试 `TestPersistentProductionGraph` 提供真实 PluginKit 装配示例。

```yaml
backend:
  use: backend/bolt
  config: {path: data/chain.db}
ledger:
  use: storage/kv
  deps: {protocol: protocol, backend: backend}
```

换为 `backend/memory` 不需要修改账本实现；数据只保留在本次 Open 的句柄中，关闭后不持久化。

独立节点 CLI 通过 node/default 管理账本生命周期，默认配置见 presets/single.yaml；集成测试另行验证存储与恢复边界。

## 落盘结构

- meta：本地格式版本、协议描述符、创世绑定、链头。
- blocks：区块哈希到完整区块，包含有序交易。
- states：区块哈希到完整状态快照，包含业务键值和账户序号。
- transactions：不透明交易 ID 到确认交易记录，包含协议编码字节、区块 ID 和块内索引。
- receipts：交易哈希到回执。
- roots 与 results：协议状态承诺与执行结果，供恢复时检查绑定。

交易索引通过可选的 `core.TransactionStore` 访问，返回 `core.ConfirmedTransaction`。它只覆盖已确认交易，待处理交易池不持久化。高度等字段由具体协议解析，不属于通用记录。

区块和交易通过 Protocol 编码为字节，再写入存储封装，恢复时通过对应协议解码；不保存 Go 接口实例，也不依赖默认格式。状态与通用元数据采用 gob 封装，保留二进制键值。当前格式为 2，旧格式 1 或缺少必要创世绑定的库会被拒绝，未提供自动迁移工具。

## 原子性与恢复

协议验证、编解码和状态承诺计算在存储锁与事务外完成，事务中重新检查 canonical head，再原子保存。具体区块的引用、序号与承诺规则由协议校验，通用存储不访问默认区块头。重复区块返回 ErrAlreadyCommitted，链头变化返回 ErrConflict。

所有记录写入和链头更新处于同一事务。默认同步开启，不设置 NoSync。若写事务回调成功但提交阶段返回错误，返回 ErrCommitUnknown，调用者应查询持久化结果后决定是否重试。

重开校验格式、协议描述符、创世 ID/承诺/编码、桶结构，以及当前链头和执行结果绑定。恢复使用私有读取实例，验证通过后才发布；并发 Stop 会取消并等待启动。不是全历史审计，也不代表已经完成硬件掉电测试。

## 验证入口

```sh
go test ./plugins/storage -v
go test ./tests/integration -run TestPersistentProductionGraph -v
```

测试包含：

- 保存后关闭并重开，读取区块、二进制键值状态、确认交易和回执。
- 注入写入中途错误，验证区块、状态、交易、回执均不可见，链头不变。
- 子进程在事务提交前直接退出，重开后仅可见旧链头。
- 子进程在提交成功后跳过 Close 直接退出，重开后数据仍完整。
- 重复提交和不同链标识被正确处理。
- 真实插件图装配后完成出块，重开后查询上一笔交易，再以连续序号继续出块。

## 当前边界

第一版每块保存完整状态快照，用于小规模验证。后续应根据数据规模设计增量状态、历史裁剪与兼容迁移，而不是把当前布局作为高吞吐链的最终存储设计。

事务行为参考 [bbolt 官方说明](https://github.com/etcd-io/bbolt#transactions)。进程退出测试验证软件提交边界，不模拟硬件故障或所有文件系统异常。

## 可选分支策略

存储依赖可选的 `BranchPolicy`，协议只需实现单父分支能力 `BranchProtocol`，不要求 `WorkProtocol`。策略通过 `Score` 生成不透明分数，通过 `Prefer` 决定是否切换，通过 `Finalized` 声明已确认祖先；存储保存每个分支的执行结果、快照、分数和最终性，并原子切换主链及确认交易、回执索引。新分支不能越过当前最终确认点；分支自身最终性也不能回退。切链时不仅要求新分支包含旧确认点，新分支自身记录的最终性也必须相同或更新；缺少同等确认的侧链可以保存，不能成为主链，避免两次切换遗忘原确认点。相同分数如何处理由策略定义。旧 `WorkProtocol` 未显式配置策略时自动使用累计工作量适配器，同工作量仍保留原链头。

策略回调只得到只读历史视图，在存储锁和事务外执行；候选区块通过参数传入，尚未存入历史。创世回调的历史只包含创世块，不传 nil。回调必须确定性执行且尊重取消；存储仍使用链头CAS和事务保证写入原子性。`PolicyID` 必须绑定规则版本及全部影响选链/最终性的配置。Bolt重开会核对策略身份，重新计算所有分支的分数、最终性和索引，再发布可用数据库。

本次分支记录格式由累计工作量字符串改为不透明分数，增加策略身份绑定；之前未记录策略身份的PoW数据库会明确拒绝打开，不自动迁移或覆盖。普通线性KV数据库继续兼容。

`ExecutionResult.Deletes` 显式删除状态键，与 `Writes` 中的nil或空value不同；删除键重复或同时存在于写入集时拒绝。执行器、模型和存储统一通过 `core.ApplyStateChanges` 应用变更；落盘结果保留删除集，分支快照和恢复重验使用同一语义。

当前实现为开发规模的完整快照及分支图，长期分支回收、修剪和大链性能尚未优化。
