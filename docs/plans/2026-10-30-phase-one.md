# 第一阶段实施计划

**Goal:** 完成消息复用、引用块正文可用性与锚定高度查询，保留完整正文链的运行能力。

**Architecture:** Router 独占 Network Handler，sync 与 body 服务注册版本化路由。交易归档独立拥有事务后端；本地补齐进入账本所有解码路径，远端补齐在导入前完成。composed 增加显式引用体模式，模式绑定创世，完整正文默认模式保持原语义。高度查询作为可选适配器沿指定 anchor 的祖先读取。

**Tech Stack:** Go、PluginKit、现有 cap/storage 与 libp2p。

## 任务与验证

1. `message/router` 与注册插件：先测试重复/未知路由、边界、取消与关闭等待，再实现。将 sync 改为 Router 消费者，更新预设与真实网络装配。
2. `archive/transactions`：先测试身份、规范编码、幂等、配额和重开，再实现事务保存及独立生命周期。
3. `body/local`、`body/fetch`、`body/server`：测试顺序、承诺、预算、故障与远端补齐；正文网络访问在账本事务外。
4. composed 引用体模式：测试未补齐拒绝执行、补齐前后 ID/线上编码不变、错误正文拒绝；模式绑定协议和创世。
5. 存储、导入及生命周期接线：写归档后提交、本地解码统一补齐、所有分支恢复校验；显式资源列表允许归档先于账本启动。测试断网重开、侧链、缺正文和归档故障。
6. `query/height` 与可选 HTTP 路由：测试主/侧链 anchor、缺失、并发 head 变化及错误传播。
7. 真实 PluginKit 装配与网络闭环；全仓 test、race、vet、gofmt、diff 检查，更新 TODO 与能力文档。

每项遵循失败测试→实现→相关测试。使用当前工作区，保留既有用户文件；本次不自动提交或推送。沿用已确认 TODO 和 2026-10-20 组合设计，按当前消费者收敛接口。

## 实施结果（2026-10-30）

七项任务已完成。新增消息 Router、独立正文归档、本地/远端补齐及请求服务、composed 显式引用模式、账本/导入/Coordinator/资源生命周期接线、锚定高度查询及可选 HTTP 路由。新增 `presets/pow-reference.yaml`，同步预设与开发网模板均注入 Router。

验证：全仓 `go test -race ./...`、`go vet ./...`、gofmt 和 `git diff --check` 通过；引用链插件图出块/重开 race 回归连续三次通过。真实网络覆盖无交易池正文的远端补齐与断网重开；存储覆盖侧链恢复、运行期缺正文、归档写入失败不推进链头。

独立审查已修复：出站并发预算、精确创世绑定、引用线上空数组的非唯一编码、本地正文故障分类及监督、服务预算拒绝不应停止节点。最终 race 还发现并修复根节点对纯取消 join 错误的停机误报。

高度能力采用有界祖先遍历；正文归档尚无 GC；两库事务允许失败时留下未引用正文。自定义同步配置必须显式增加 Router，新消息封装要求网络节点一起升级。工作保留在本地，未提交或推送。
