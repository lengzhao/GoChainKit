# 可组合存储与密钥保存实施计划

**Goal:** 将账本事务后端和密钥保存从链规则、网络传输中分离，使用类型化 Deps 组合。

**Architecture:** core 不变。cap/storage 定义事务型命名空间 KV 后端及打开器，账本拥有打开后的数据库生命周期；cap/keystore 定义最小机密保存和口令来源，签名继续使用 cap/signer。libp2p 身份通过专属适配器读取保存能力，网络传输不读写密钥文件。

**Tech Stack:** Go、PluginKit、现有 bbolt、标准库 AES-GCM、既有 golang.org/x/crypto/scrypt。

用户已批准存储/密钥分层与最小实现方向。不保留无必要的兼容别名；账本格式 2 与链规则保持不变。现有加密前的网络身份文件不自动覆盖或转换。

## 设计取舍

1. 继续让每种账本直接依赖数据库：变更小，但换数据库需重复账本逻辑。
2. 最小事务 KV 接口与账本分离（采用）：真实消费方驱动抽象，保留现有事务/恢复语义，可用内存和 Bolt 验证替换。
3. 一次性加入 SQL、远程存储、状态树、缓存、钱包管理：当前没有消费者，不在本轮增加。

后端接口必须明确快照、提交/回滚、扫描顺序、对象所有权、事务句柄有效期和关闭行为。打开器构造不做 IO；每次 Open 返回一个独立拥有的句柄，避免多个 ledger 隐式共享资源。账本依赖后端，不依赖具体数据库插件。命名空间对应现有顶层 Bolt bucket，不改变线上协议或磁盘记录编码。

密钥保存的是显式可导出的本地机密；它不成为 cap/signer 的必选接口，未来不可导出签名设备无需实现该 Store。口令只通过 SecretSource 注入，不进入 YAML。加密使用固定版本及有界 KDF 成本、随机 salt/nonce、绑定记录 ID 的认证数据；拒绝错误口令、篡改、非法 ID、超大记录。发布完整且同步的独占文件，不替换并发创建者的密钥。构造不访问文件、环境或生成密钥。
