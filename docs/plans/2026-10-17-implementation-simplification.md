# 实现简化与职责重构计划

**目标：**在保持交易、共识、持久化规则不变的前提下，修正依赖方向，提取可组合运行能力并减少重复实现。

**架构：**领域实现不依赖插件注册层。共识运行器通过类型化 Deps 使用同步和区块导入服务；存储复用内部准备流程，保留后端原子提交所有权。composed 执行统一由独立 Executor 提供。

**技术栈：**Go、PluginKit、libp2p、Bolt。

1. 将 KV 执行语义放入 protocol/kv，插件成为薄适配层，powkv 显式接收内层执行器；依赖及配置回归。
2. 提取独立同步与导入能力，PoW 仅负责挖矿调度及故障监督；更新插件依赖图、配置和真实网络测试。
3. 共享 Memory/Bolt 分支导入准备，按需读取分支记录，并按脱离/附加分支增量更新规范链索引；验证回滚、finality、重组和恢复。
4. composed 仅通过独立 Executor 执行，删除 Base 具体类型桥接及协议执行入口；验证普通与上下文模型一致。
5. 提取内部严格 JSON 解码助手，用显式深复制代替 Envelope JSON 往返；保留各模型签名/编码校验和空值区别。
6. 独立审查后运行全仓 race、vet、格式检查及真实多节点回归。新接口必须有实际消费方和替换意义；不新增共识算法，不改线格式和数据库版本。


## 实施记录

六项实现已落地，独立审查确认分层、执行入口、编码隔离及存储 CAS/最终性/增量索引边界。同步停止增加请求门禁和在途处理器 join；混合取消与本地故障保留完整错误。

真实三矿工测试暴露独立并发运行后的传播活性问题：合法交易进入弱分支却不在当前主链确认时，原逻辑没有回收入池。通过确定性等工作量侧链测试先复现，再复用重组回收逻辑修复，保持选链规则不变。最终全仓 `go test -race ./...`、`go vet ./...`、格式与差异检查通过；single、pow、pow-account、pow-utxo 四份 CLI 配置均完成隔离临时目录中的启动与磁盘重开。三矿工专项 race 另连续运行两次通过。
