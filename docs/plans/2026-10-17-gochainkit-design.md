# GoChainKit 架构草图

> 后续协议接口已重构，具体类型不再属于框架核心。当前接口和目录以 [模块与协议接口](../interfaces.md) 为准，本文保留初版设计历史。

状态：2026 年 10 月 17 日已通过用户评审。本文描述设计方向，不代表接口或实现已完成。

## 目标与范围

使用 Go 构建模块化区块链框架，以 PluginKit 注册插件、解析配置并装配依赖图。参考 AgentKit 的装配方式，定义独立的区块链领域契约。开发者通过选择模块和配置，组装一条新链。

第一版为各核心模块提供最小实现，完成单节点交易、出块、执行、持久化和恢复闭环。多节点安全共识、分叉选择、跨链及通用智能合约虚拟机暂不纳入最小实现；模块边界需允许后续扩展。

## 装配方案

可选方案：手工构造所有模块最简单，但配置组装能力弱；全事件总线较灵活，但会隐藏依赖和关键提交顺序；PluginKit 显式依赖图更符合项目目标。

建议采用 PluginKit 显式依赖图：构造函数负责配置校验与依赖注入，不启动后台任务；Node 统一驱动运行和关闭。关键执行路径使用明确的方法调用，事件用于通知与观测。

插件首先采用编译期注册，通过配置选择具体实现。运行时动态加载或热替换暂不作为第一版目标。PluginKit 的准确 API、生命周期与错误处理行为，在正式编写代码前对照上游源码验证。

## 模块与最小实现

- Node：装配结果入口，管理启动、关闭与健康状态；最小实现为单进程节点。
- Transport：对等节点连接及消息传输；最小实现为无对等节点的单节点传输，不能验证多节点传播。
- Mempool：交易准入、去重、容量控制、选取与移除；最小实现为有界内存队列，重启后待处理交易可丢失。
- Consensus：接收提议和共识消息、产生确定提交的区块；最小实现为单节点定时出块，仅供开发。
- BlockBuilder：按链头及资源限制组装候选区块，与候选执行结果；最小实现按交易池顺序打包。
- Executor：对交易进行确定性验证与执行，产出状态变化和回执；最小实现为带签名和序号的键值写入交易，不含费用机制。
- StateStore：提供已提交状态读取和隔离执行视图，并计算状态根；最小实现使用本地数据库及规范化状态哈希规则。
- ChainStore：查询区块、回执、链头；最小实现与状态共享一个本地数据库后端。
- Committer：检查父链头并原子提交区块、状态、回执和新链头；最小实现使用共享数据库的写事务。
- API：提交交易并查询区块、状态、回执；最小实现为 HTTP 接口。
- Crypto：签名、验证和哈希算法契约；第一版固定一套标准算法，不自行设计密码算法。

StateStore、ChainStore 和 Committer 的接口分离不意味着存储可以任意混搭。第一版要求共享事务后端，装配阶段拒绝不兼容的组合。

## 公共数据契约

先确定 Hash、Address、Transaction、BlockHeader、Block、Receipt、ExecutionResult 与 Genesis。

- Transaction：链标识、发送者、公钥或公钥解析规则、序号、操作及签名；规定签名域与规范编码。
- BlockHeader：协议版本、高度、父区块哈希、交易根、状态根、回执根及共识所需字段。
- ExecutionResult：绑定父状态和候选区块的写入集、回执、状态根；执行结果不能与任意区块混用。
- Genesis：初始状态、链标识、协议参数与共识初始配置；所有节点须使用一致的创世规则。

规范编码、排序、哈希算法与协议版本构成全网一致性契约。不得依赖 Go map 的遍历顺序。执行不能直接读取本地时间、随机数、外部网络或本地环境；需要的输入必须由协议定义。

## 核心接口方向

以下为职责草图，尚非可直接编译的完整接口。

```go
type Mempool interface {
    Add(ctx context.Context, tx Transaction) error
    Select(ctx context.Context, maxBytes int) ([]Transaction, error)
    Remove(ctx context.Context, ids []Hash) error
}

type Executor interface {
    Execute(ctx context.Context, parent StateReader, block Block) (ExecutionResult, error)
}

type Committer interface {
    Commit(ctx context.Context, expectedHead Hash, block Block, result ExecutionResult) error
}

type Node interface {
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
}
```

Consensus 的完整方法签名需单独评审其驱动方式：区分提议构建、提议验证、共识消息处理和最终提交。避免将可替换共识约束为简单的定时 ProduceBlock 方法。

## 交易处理闭环

1. API 接收交易，校验大小、规范编码、链标识和签名；Mempool 进行准入及去重。
2. Consensus 触发提议，BlockBuilder 基于明确链头选取交易。
3. 在隔离视图中执行候选交易，得到状态变化、回执和各类根；构造完整区块。
4. 单节点共识确定该区块。未来多节点实现必须重新验证收到的提议并按共识规则决定提交。
5. Committer 校验父链头与执行结果匹配，以一个事务提交区块、状态、回执和链头。
6. 提交成功后移除已打包交易，再发布通知。通知失败不撤销已经提交的区块。
7. 重启时恢复创世配置和最后已提交链头，检查对应状态可读，再开放请求。

提交期间发生取消或连接中断时，调用方不能仅凭错误断言未提交，应通过区块哈希和链头查询确定结果。重复提交需可识别，不能重复应用状态变化。

## 生命周期和兼容性

Node 启动前完成依赖、配置和协议兼容性校验；依赖先启动，使用者后启动，部分启动失败时逆序释放已启动资源。关闭时先停止接受请求和新提议，再排空或终止执行，最后关闭持久化资源。

依赖图必须无环。Consensus 通过 Node 协调器获取提议服务，不反向依赖 Node。共享存储实例仅关闭一次。

区分可本地调整的端口、日志和队列容量，与必须由链协议约束的编码、执行语义及共识规则。第一版通过停机修改配置切换实现；影响协议的更换需要专门升级规则。

## 目录建议

```text
cmd/gochainkit/       命令行入口
core/types/          公共协议类型和编码
core/      模块接口
node/                编排和生命周期
plugins/             各模块最小实现和注册
presets/             单节点配置
internal/            内部工具
tests/integration/   端到端及恢复验证
docs/                架构与使用说明
```

## 第一版验收

- 配置可装配并启动单节点；错误依赖和不兼容存储组合在启动前报错。
- 有效交易可提交、打包、执行、查询；非法签名、错误链标识及重复序号被按规则拒绝。
- 相同初始状态和区块输入，独立执行得到相同的状态根与回执。
- 原子提交失败不会留下区块、状态和链头不一致的可见结果。
- 重复提交、执行取消和链头变化不会重复应用交易。
- 正常重启及模拟中断恢复后，链头与状态一致。
- 生命周期中资源可释放，后台任务可终止。

## 下一步评审

先确认模块边界与单节点最小范围，再确定共识驱动接口、规范编码、状态根规则和本地存储后端。随后制定实现计划并编写 Go 接口与最小插件。
