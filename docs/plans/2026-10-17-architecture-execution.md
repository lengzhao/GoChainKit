# 架构评估执行计划

用户已授权按架构评估的推进顺序直接执行。本计划不包含状态树、VM、对等网络或分布式共识实现。

1. 第一批：用同一 Ledger owner 绑定读写，构块器声明账本身份，构造时拒绝混用；交易错误区分拒绝与延后，默认构块有限次跳过或驱逐，单节点共识遇到暂时无提议/链头竞争继续运行；用 CommittedError 表达提交后维护失败。保留协议格式中立与事务内 CAS。
2. 第二批：实现可运行根 Node，监督后台任务，按序启动、部分失败回滚、逆序关闭并去重资源；通过 PluginKit 加载配置及默认 preset，提供 CLI 和真实启动烟雾测试。
3. 第三批：消费者依赖小协议能力组合，交易池仅保管候选，默认 selector/fifo 独立选择；存储独享的准备助手内部化，清理未使用接口和默认重复 DTO，减少默认执行器重复配置。

按任务补行为测试，复现失败后实现。每批普通测试与适当 race 检测，最终全仓测试、vet、真实 CLI 重开验证与独立审查。修复已经识别的问题后才完成交付，不把测试桩当作运行节点。
