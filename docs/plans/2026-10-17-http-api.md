# HTTP API 实施计划

**Goal:** 提供协议无关的交易受理、链查询与节点信息，以及按需装配的账户/UTXO查询。

**Architecture:** cap/query 定义传输无关能力，api 提供领域服务；api/http 和 plugins/api/http 适配 HTTP 与 PluginKit。HTTP 路由扩展独立装配，通用服务器不按模型名分支。core 不增加 API 方法，无旧 API 兼容要求。

**Tech Stack:** Go 标准 net/http、现有 PluginKit/内存与 Bolt 后端。

## API 契约

- POST /v1/transactions：严格 JSON {"data":"<Base64协议交易字节>"}。未确认交易返回202 accepted；已确认返回200 confirmed。受理不代表上链、最终性或永久保留，重复提交幂等。
- GET /v1/chain/head：一次取得 head，再查询该明确 ID 的区块/状态根。
- GET /v1/blocks/{id}：原协议编码字节与 ID；不强制默认 Header/高度。
- GET /v1/transactions/{id}：confirmed 或 bounded pool 的 pending；未知404。确认结果是某次读取观察到的 canonical 状态，带观察 head 和包含 block。
- GET /v1/receipts/{id}：原协议回执字节、包含 block 与观察 head。无回执或未确认404。
- GET /v1/node：协议描述符、可用网络地址/对端信息；不提供钱包私钥及管理操作。
- ID/Commitment 使用 hex，数据使用 Base64，uint64金额/序号等JSON用十进制字符串，避免客户端精度丢失。
- 状态查询 ?at=<hex block ID>；缺省只解析一次head，返回实际锚点；不把原始全状态/任意状态键暴露为通用endpoint。
- 错误统一 {"error":{"code":"...","message":"..."}}。输入/协议交易错误与本地故障分开；混合错误必须保留真正故障，不以NotFound/Full/取消吞掉它。
